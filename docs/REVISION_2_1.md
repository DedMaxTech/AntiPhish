# Дополнения AntiPhish 2.1

Все команды используют тот же Analyzer, каталог брендов и правила решения. Отдельный облегчённый движок и отдельное обобщение образцов на экспорт не создавались.

## Пакетная обработка

```powershell
python -m antiphish batch C:\Mail --output reports\mail.json
python -m antiphish batch C:\Mail\letters.zip --extensions .eml --output reports\mail.json
python -m antiphish batch C:\Mail\letters.zip --extensions .eml --output reports\mail.json --resume
```

Папка просматривается рекурсивно; ZIP и TAR читаются без распаковки файлов по именам из архива. Для архива с письмами и копиями исходников полезно указать `--pattern '*/eml/*'`: иначе оригиналы и обработанные письма будут отдельными объектами. Принимаются поддерживаемые анализатором письма, документы, HTML и изображения; README и реестры не анализируются. Вложенный ZIP остаётся одним анализируемым объектом со своими дочерними вложениями.

Результат содержит `results` и `statistics`. У каждого объекта есть устойчивый ID, относительное имя `source`, SHA256, дата анализа, время и полный `report`. Совпадающие байты одного формата внутри пакета обрабатываются один раз, остальные результаты указывают `duplicate_of`. Ошибки отдельных файлов не прерывают весь пакет. В статистике отдельно считаются COMPLETE/PARTIAL/FAILED, вердикты, сетевые статусы, частота причин, общая длительность и P95. FAILED не включается в количество отрицательных вердиктов. Пустой пакет и нарушение общего лимита возвращают ненулевой код CLI.

Рядом с итоговым JSON пишется журнал `mail.json.jsonl`. Он пополняется после каждого объекта. `--resume` использует только полные результаты с совпадающими байтами, настройками, версией исходников, каталогом и снимками данных. Частичные проверки выполняются заново. Истёкшие по календарной дате записи базы не переиспользуются на следующий день; сетевые результаты старше часа также выполняются заново. Прерванная последняя строка журнала не мешает восстановлению.

Ограничения пакета по умолчанию: 2000 элементов архива/объектов, 200 МиБ суммарных входных данных, 50 МиБ на отдельный файл, контроль коэффициента сжатия. Лимиты можно настроить через `Limits` в Python. Серверные загрузки ограничены 50 МиБ плюс небольшой запас на multipart. Символические ссылки, переходы `../`, абсолютные пути и зашифрованные элементы пропускаются с явной ошибкой. Это не параллельный GPU-конвейер: один постоянный Analyzer последовательно обрабатывает письма и переиспользует загруженные модели.

`--persist` дополнительно сохраняет JSON-отчёты в `reports/history.sqlite`. Исходное письмо в историю не копируется. Отчёт может содержать название файла, отдельные цитаты и объяснения, поэтому история тоже относится к данным анализа.

## API и Swagger

```powershell
python -m pip install -e '.[api,ocr,active]'
python -m antiphish serve
```

Swagger: <http://127.0.0.1:8000/docs>. API предназначен для внутренних вызовов. По умолчанию он слушает localhost, авторизации нет. Настройки адреса и порта задаются `ANTIPHISH_API_HOST` и `ANTIPHISH_API_PORT`. API и batch по умолчанию работают без сети; одиночный CLI сохраняет прежний HTTP по умолчанию.

| Метод | Путь | Для чего |
|---|---|---|
| POST | `/analyze` | URL или файл по пути на машине API |
| POST | `/analyze/file` | Загрузка EML, HTML, документа или изображения |
| POST | `/batch` | Папка или архив по пути на машине API |
| POST | `/batch/file` | Загрузка архива |
| GET | `/reports` | Последние отчёты без их полного содержимого |
| GET | `/reports/{id}` | Сохранённый результат |
| GET | `/knowledge` | Размеры основных таблиц и возраст фидов |
| GET | `/reasons` | Справочник кодов и их роль в решении |
| GET | `/health` | Версия и состояние файлов конфигурации |

Пример тела `/analyze`: `{"source":"/inputs/message.eml","profile":"quality","network":"offline","persist":true}`. Для `/batch` можно добавить `extensions:[".eml"]` и `pattern`. Browser требует `confirm_browser_risk:"I_UNDERSTAND"`. Запрос ждёт полного результата; брокера заданий и отдельной очереди нет. Крупный пакет удобнее запускать CLI с журналом и возобновлением. Внутри сервера анализы сериализуются, чтобы не перемешивать бюджеты OCR и конкурирующие загрузки GPU-моделей.

## Linux и Docker

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[api,ocr,active,dev]'
.venv/bin/python -m playwright install --with-deps chromium
.venv/bin/python -m antiphish setup-ocr
.venv/bin/python -m antiphish serve
```

Headless CLI не импортирует Tkinter. GUI требует отдельно установленного Tkinter и графического окружения. Без переменных окружения установленный пакет на Linux хранит данные в `$XDG_DATA_HOME/antiphish` или `~/.local/share/antiphish`. В исходном проекте остаётся каталог проекта. Edge используется на Windows; Linux выбирает Chromium, установленный Playwright. Свой исполняемый файл задаётся `ANTIPHISH_BROWSER_EXECUTABLE`.

```bash
docker compose up --build -d
# CLI внутри контейнера:
docker compose exec antiphish antiphish analyze /inputs/benign-corporate.eml --network offline
```

Compose публикует API только на `127.0.0.1:8000`, запускает непривилегированного пользователя, монтирует систему файлов контейнера только для чтения и даёт отдельные `/tmp` и том данных. Каталоги `models` и `samples` подключаются только для чтения. `.dockerignore` исключает рабочие базы, письма, архивы, отчёты и большие веса из контекста сборки. Образ содержит код, каталог брендов, зависимости и Chromium. Фиды и OCR-веса в него не включаются: их подготавливают отдельно.

Для deep можно собрать `docker build --build-arg EXTRAS=api,ocr,active,deep -t antiphish:deep .` и подключить заранее скачанные модели. GPU в Docker требует настроенного NVIDIA Container Toolkit. Обычный контейнер и WSL-проверки подтверждены отдельно; GPU-deep в Docker не проверялся. Отдельный профиль браузера и контейнер не равны полноценной виртуальной машине для вредоносного кода.

## Домены и бренды

```powershell
python -m antiphish import-domains security-allowlist-domains.csv
```

Переданный CSV не является проверенным списком безопасности. После нормализации принято 22 853 домена; 109 публичных/частных суффиксов и две записи доменов для примеров отброшены. Используется отдельная индексированная SQLite. Совпадение точного хоста появляется в `configuration.domain_context`, но не влияет на вердикт, не распространяется на поддомены и не пропускает посещение страницы. Google Docs, доверенный сервис или скомпрометированный известный сайт не становятся безопасными из-за попадания в CSV.

Активный каталог расширен с 75 до 126 идентичностей: добавлены российские страховые компании, магазины, сервисы работы и поездок, банки и международные бренды исходного корпуса. Часть официальных корней проверена по заголовку и фактическому адресу ответа; для закрытых сайтов использованы документы и страницы самой организации. Неустановленные домены остаются в неактивных кандидатах. Общие названия вроде «МФЦ» не приписываются единственному региону. Имена из исходных 175 брендов могут быть дублями, продуктами одного владельца или неоднозначными названиями; число записей не означает полное покрытие всех вариантов входа. После ручного изменения каталога или модели перезапустите API.

## Активное содержимое и объяснения

В PDF исследуются реальные словари действий и ссылки на объекты, включая сжатые JavaScript-потоки. Отдельно фиксируются JavaScript, запуск программ, SubmitForm, ImportData, удалённые переходы и встроенные файлы. Извлекаются URL и признаки чтения/отправки полей; скрипты не выполняются. Текстовое упоминание `/JavaScript` в инструкции больше не считается активным действием. Есть предел числа объектов, времени просмотра и размера декодированного кода. Лимит изображений PDF общий для документа, а не повторяется для каждой страницы.

VBA извлекается oletools в отдельном процессе с ограничением времени и контролем памяти. Отчёт содержит отпечаток модуля, признаки автозапуска, сети, запуска процессов и динамического кода. Сам макрос не выполняется, внешние шаблоны не загружаются. Отсутствующий парсер, неподдержанное сжатие или превышение бюджета дают ограничение анализа.

Буквальный `document.write(atob(...))` или HTML-присваивание с percent-кодированием восстанавливается статически с ограничением вложенности. Восстановленные формы получают отдельную область и источник `decoded-script`: содержимое не объявляется реально выполненным и само по себе не создаёт PHISHING. Закрытые HTML-dialog и содержимое template не считаются активными формами. Это устраняет ложные тревоги на интерфейсе обычного PDF-просмотрщика.

QR ищется на изображениях и browser-снимках; при неудаче мультидетектора выполняется одиночная проверка, затем инверсия, нормализация контраста и бинаризация. Выдаётся найденный адрес, а не утверждение, что любой QR опасен. Обход следует по найденному адресу с теми же ограничениями.

У форм теперь есть XPath и безопасное структурное описание без значений полей. У страниц — типизированные ссылки на изображения, скрипты, iframe, CSS и favicon. Кроме прежнего отпечатка есть структура DOM с вложенностью, без текста и атрибутов; для снимка возвращается SHA256. Время разбито на извлечение, сеть, базы/бренды, модели и решение. `analysis_status=PARTIAL` относится ко всей запрошенной проверке; `static_analysis_status` отдельно показывает, что статический разбор мог завершиться полностью. Ошибка сети не отменяет уже доказанный фишинг.

`python -m antiphish --log-json batch ...` выводит диагностические JSON-записи в stderr без тела письма и адресов переходов. Глобальная статистика пакета считает коды по письмам, а не по количеству повторов одной причины на странице.

## Проверка качества и актуальности

```powershell
python -m antiphish benchmark-dataset letters.zip --kb empty.sqlite --output reports\quality.json
python -m antiphish audit-dataset letters.zip --output-dir reports\audit --check-links --max-urls 120
python -m antiphish capture-urls urls.txt --output-dir data\private\captures --max-urls 100
```

`benchmark-dataset` читает ZIP с `manifest.jsonl`. Для каждой строки нужны ID, путь, метка phishing/benign, желательно SHA256, источник, дата, язык и `group_id`. Для сохранённого HTML указывается исходный `url`, чтобы относительные формы разбирались правильно. Предоставленный формат с `evaluation_path`, `sha256_evaluation`, `subset` поддерживается напрямую. Исходные метки не импортируются в KB и не участвуют в обучении.

Строгий PHISHING и PHISHING+SUSPICIOUS считаются отдельно. Публикуются полнота анализа, сетевые статусы, группы, источники, языки, recall/FPR и интервалы Wilson. Ошибки не выбрасываются из знаменателя ради красивого recall. Ноль ложных срабатываний на 500 письмах соответствует верхней границе примерно 0,76% при 95%, а не доказанному нулю. Сравнение версий требует одинаковых ID, хешей и меток; для него есть парный bootstrap по группам. Независимо проверенные метки имеют отдельный блок статистики. Если их нет, он остаётся пустым.

Аудит создаёт очередь пересмотра меток и отмечает старые письма, заглушки и отсутствие навигационных адресов. Разделение по группам предлагается для последующих экспериментов; уже просмотренный набор не превращается в новый независимый тест. Проверка ссылок фиксирует дату, HTTP-статус, конечный адрес, заголовок и отпечаток тела. Токенизированные, личные и адреса-заглушки не открываются. Доступность адреса не является меткой phishing/benign.

Для новых тестов следует сохранять страницу в момент подтверждения атаки, сохранять происхождение и разметку, отделять новые кампании по времени и шаблонам, затем проверять ту же сохранённую страницу одинаково для всех версий. Живое посещение — отдельная проверка доступности и обхода; оно не должно ежедневно менять смысл одного и того же теста. Недоступные страницы, CAPTCHA и неизвестная разметка учитываются отдельно. Реальная российская легитимная почта должна включать банки, покупки, доставку, авторизацию, бухгалтерию, госуслуги и рекламные письма. Linux-рассылка не заменяет эти случаи. Современные синтетические парные сценарии полезны как регрессии, но не выдаются за реальную почту.

Результаты переданного 540-письменного набора, проверка внешнего PhreshPhish и оговорки собраны в WORK_STATUS. Полную объективную разметку нельзя автоматически получить из неизвестных меток и работающих URL: очередь требует независимой проверки.

## LLM и распознавание логотипов

Qwen остаётся извлекателем фактов с точными подтверждёнными цитатами. Совместимую заранее скачанную мультимодальную модель можно задать через `ANTIPHISH_LLM_MODEL_DIR`. Загрузчик использует локальные файлы, Safetensors и не разрешает remote custom code. [Gemma 3 4B](https://huggingface.co/google/gemma-3-4b-it) — кандидат для сравнительного теста текста и изображения, а не доказанная замена; требуется принятие её лицензии. Англоязычные специализированные классификаторы тоже требуют отдельной российской проверки.

[Granite URL QLoRA](https://huggingface.co/bengoldberg0/granite-4.2-3b-phishing-url-qlora) рассматривает только строку URL. По опубликованному внешнему тесту у него 64% false-positive rate и 72,8% recall. Его автор прямо ограничивает применение исследованием. Он не подключён к решению AntiPhish.

[Horizon-Labs multilingual classifier](https://huggingface.co/Horizon-Labs/phishing-scam-detector-base) скачан в закреплённой ревизии и отдельно проверен на 540 письмах. При пороге P(fraud)=0,5 он отметил 8/40 фишинговых и 0/500 легитимных писем. Он обучен преимущественно на синтетических сообщениях, поэтому не заменяет анализ маршрута и формы. `setup-text-model` скачивает веса; `ANTIPHISH_TEXT_MODEL_DIR` включает только дополнительные оценки. Spam и fraud разделяются: рекламный текст не становится фишингом из-за суммы двух классов. По умолчанию этот эксперимент выключен.

Для логотипов добавлен индекс проверенных изображений на существующем SigLIP2. Галерея содержит `manifest.jsonl` с `path`, `brand`, официальным `source_url` и `reviewed:true`. `index-logos <folder>` строит векторы; `match-logo <image>` возвращает кандидатов, сходство и область снимка. При наличии индекса deep добавляет такие наблюдения к отчёту. Сейчас проверена маленькая галерея из трёх официальных favicon. Это функциональная проверка сопоставления, не измеренная полнота распознавания всех брендов.

RTX 4080 с 16 ГБ подходит для дообучения небольшого детектора области логотипа и классификатора/сопоставления эмбеддингов. Главная работа — собрать проверенные версии русских логотипов, разметить их рамки на реальных страницах и добавить сложные отрицательные примеры: платёжные значки, кнопки входа через чужой сервис, партнёры и рекламные блоки. Делить нужно по страницам/кампаниям, а не по случайным копиям одного изображения. До такой разметки модель не обучалась и визуальные кандидаты не используются как самостоятельное доказательство подмены. Даже правильно распознанный логотип может находиться на легитимной партнёрской странице.


## Измерения версии 2.1 на этой машине

Проверено на i5-12600KF, 64 ГБ RAM, RTX 4080 16 ГБ и Python 3.13.6 в Windows. Один постоянный Analyzer, без сети; fast/quality — 540 писем, deep — все 40 phish и 40 benign из этого набора. Поэтому строки показывают стоимость конкретной работы, а не универсальную производительность.

| Профиль | Объектов | Время с записью отчёта | Объектов/мин |
|---|---:|---:|---:|
| fast/offline | 540 | 16,61 с | 1 951 |
| quality/offline | 540 | 20,00 с | 1 620 |
| deep/offline | 80 | 700,42 с | 6,85 |

У deep первый объект занял 22,73 с с загрузкой модели; последующие в среднем 8,58 с, P95 всего прогона — 12,84 с. Максимум памяти CUDA в процессе — около 10,13 ГиБ. Зафиксированы версии, входные ID и отпечатки. Внешние сайты, изображения, PDF и макросы меняют стоимость обработки, поэтому скорость на этом наборе нельзя обещать для любой почты. Итоги: reports/revision-2026-10/performance-final.json и deep-final-summary.json. Возобновлённые объекты не использовались для расчёта скорости первичного анализа.

На 40 phish quality отметил 34, deep — 35; strict PHISHING в offline-тесте не было. На 500 benign quality — 0 предупреждений, deep на своих 40 benign — 0. Для доказательства качества нужны новые независимо размеченные российские письма; полный разбор ограничений находится в WORK_STATUS.md.

Повторение проверки: python docs/benchmark_revision.py --dataset letters.zip --output-dir reports/check. Для дополнительного архива сохранённых страниц добавляется --extra-dataset pages.zip. Во время этого запуска текстовый эксперимент включится только при явно установленном ANTIPHISH_TEXT_MODEL_DIR. Сам скрипт deep не запускает.
