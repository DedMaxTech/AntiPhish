# AntiPhish 2.1

Локальный анализатор писем, ссылок и вложений с разбором русских сценариев мошенничества. Принимает EML, MIME, HTML, URL, PDF, Office, ZIP и изображения. Возвращает вердикт, конкретные причины, цепочки переходов, формы и получателей данных.

Модели и проверка репутации работают локально. **CLI и GUI по умолчанию используют HTTP**: переходят по ссылкам из письма, поэтому сайт видит запросы и адрес клиента. Для проверки без сетевых обращений укажите `--network offline`. Репутационные сервисы при анализе письма не вызываются.

В версии 2.1 добавлены пакетный анализ папки/ZIP/TAR, внутренний FastAPI со Swagger, история отчётов, Linux/Docker, структурный разбор активного PDF и VBA, восстановление буквального HTML smuggling и проверка качества по внешним корпусам. Полное актуальное описание, инструкции и замеры — в [документации Markdown](docs/AntiPhish_documentation.md). Вводный материал — [«Предметная область»](docs/Предметная_область.docx). Результаты ревизии и состояние работ — в [docs/WORK_STATUS.md](docs/WORK_STATUS.md).

## Запуск в этом проекте

Окружение, локальная база репутации и русский OCR уже подготовлены.

```powershell
cd D:\Projects\Python\AntiPhish
.\.venv\Scripts\python.exe -m antiphish gui
.\.venv\Scripts\python.exe -m antiphish doctor
.\.venv\Scripts\python.exe -m antiphish analyze "C:\Mail\message.eml" --network http
```

Сохранить JSON или полностью отключить сеть:

```powershell
.\.venv\Scripts\python.exe -m antiphish analyze "C:\Mail\message.eml" --network offline --output "C:\Mail\result.json"
```

Коды завершения: `0` — достаточных признаков не найдено, `10` — требуется проверка, `20` — фишинг, `30` — анализ не выполнен. Частичный анализ указан отдельно и не превращается автоматически в фишинг.

## Решение и защита от ложных срабатываний

`PHISHING` требует точного совпадения с действующим подтверждённым IOC либо связанного доказательства: на конкретной странице заявлен сервис, запрашивается пароль, OTP, данные карты или секрет кошелька, а получатель не относится к этому сервису. Факты разных страниц не складываются в искусственный фишинг. Демо-форма, обычный счёт, банковские слова, кириллица, логотип платёжной системы, сокращатель ссылки или вывод LLM сами по себе не блокируют письмо.

`SUSPICIOUS` означает предупреждение для проверки: неподтверждённая акция бренда с внешним переходом, подмена формы без установленной отправки, вероятный шаблон кампании, совпадение с общественной базой, подозрительное вложение. Это не подтверждённый вредоносный объект.

`NOT_DETECTED` означает отсутствие достаточных доказательств в доступных данных. GUI показывает неполную проверку серым, отдельно отображает сетевые ошибки, отсутствующие модели и ограничения разбора.

Сходство домена, бренда и модельные оценки не являются откалиброванными вероятностями. Заголовок From и Authentication-Results внутри произвольного EML не рассматриваются как доказательство подлинности отправителя.

## Ссылки и формы

Обход хранит граф `письмо → ссылка/QR/вложение → промежуточная страница → целевая страница → форма → получатель`. Лимиты: 12 страниц, 4 уровня переходов, общий бюджет 45 секунд. Используется полный адрес, поэтому две разные страницы одного домена не теряются. Подписи и порядок параметров сохраняются при обращении; токены и адреса в параметрах скрываются в JSON.

Разбираются HTTP-редиректы, meta refresh, статические JS-переходы, буквальное base64/Unicode-кодирование, Google `/url`, SafeLinks, VK `/away.php`, ссылки в опубликованных Google Sheets, включая промежуточный `pageUrl`, ссылки в Office/PDF и QR. Ресурсы оформления и адреса отправки форм не обходятся как навигационные ссылки. Ссылки с токеном действия, например подтверждением операции, пропускаются.

HTTP не исполняет JavaScript. Для динамических страниц:

```powershell
.\.venv\Scripts\python.exe -m antiphish analyze "C:\Mail\message.eml" --network browser --confirm-browser-risk I_UNDERSTAND
```

Browser запускает отдельный временный контекст Edge на Windows или Chromium на Linux без общей сессии, сервисных воркеров и загрузки файлов. GET проходят через транспорт с закреплёнными публичными IP и проверкой TLS; редиректы также проверяются. Запросы к локальным адресам и отправка форм блокируются. WebSocket не подключаются, WebRTC отключён. При зависании JavaScript завершаются только дочерние процессы браузера этого запуска; драйвер Playwright остаётся работоспособным для следующего письма.

После загрузки browser может пройти до трёх клиентских шагов входа на вымышленных данных. До первого заполнения блокируется весь HTTP-трафик, включая GET, картинки и beacon. Попытка передать тестовый пароль или OTP фиксируется вместе с адресом получателя, но запрос не отправляется. Результаты содержат `synthetic_only=true`, `transmitted=false`; тела запросов и значения тестовых секретов не сохраняются. Если следующий шаг требует ответа сервера, обход останавливается с указанием ограничения. Произвольные покупки, платежи и кнопки вне сценария входа не выполняются. Браузер не является виртуальной машиной; browser остаётся отдельным явно выбираемым режимом.

## Русский OCR

В `quality` и `deep` используется локальный RapidOCR с ONNX-моделью PP-OCRv5 для кириллицы, включая русский и латинский текст. OCR подключён к изображениям в MIME, сканированным страницам PDF и снимку browser-страницы. QR разбирается отдельно. Текст OCR может дать предупреждение, но не создаёт выдуманную форму или основание для блокировки.

Установка в новом окружении:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[ocr,dev]"
.\.venv\Scripts\python.exe -m antiphish setup-ocr
```

`setup-ocr` скачивает три модели из официального репозитория RapidAI и проверяет фиксированные SHA256. При анализе отсутствующие модели не скачиваются автоматически. Лимиты OCR: 6 изображений на анализ, сторона до 1800 пикселей, прекращение дополнительных вызовов после 12 секунд работы. Общий предел изображения — 30 млн пикселей. Tiny/tracking images не распознаются. OCR может ошибаться на мелком, размытом или необычно оформленном тексте.

## Локальная репутация

```powershell
.\.venv\Scripts\python.exe -m antiphish update-feeds
.\.venv\Scripts\python.exe -m antiphish feed-status
```

Обновляйте снимки раз в 1–3 дня. Они находятся в `artifacts/knowledge.reputation.sqlite`, отдельно от собственной базы образцов. При ошибке загрузки, неожиданном сокращении списка или неверном формате сохраняется предыдущий снимок. Замена каждого источника выполняется транзакционно. Через 7 дней записи перестают участвовать в решении до успешного обновления. Источник и возраст видны в отчёте и GUI.

По умолчанию скачиваются:

- [Phishing.Database](https://github.com/Phishing-Database/Phishing.Database): обширный общественный список, лицензия MIT с сохранением уведомления об авторстве. Совпадение даёт предупреждение; весь домен автоматически не блокируется.
- [OpenPhish Community](https://openphish.com/phishing_feeds.html): ограниченный список подтверждённых URL; точное действующее совпадение может дать `PHISHING`. [Условия OpenPhish](https://openphish.com/terms.html) разрешают личные, академические и независимые исследовательские цели; отсутствие прибыли само по себе не разрешает эксплуатацию в деятельности организации. Перераспространение фида требует согласия. Снимок не включается в wheel.

На 05.10.2026 локально установлено 787653 записи Phishing.Database и 300 OpenPhish. Это число записей источников, а не гарантированное число уникальных актуальных атак; оно меняется при обновлении.

Опционально доступен [PhishTank](https://phishtank.org/developer_info.php), только verified+online:

```powershell
$env:ANTIPHISH_PHISHTANK_KEY = "your-application-key"
.\.venv\Scripts\python.exe -m antiphish update-feeds --provider phishtank
```

Без ключа источник может отвечать 403; рабочие снимки остальных источников сохраняются. Ключ скрывается в сообщениях об ошибках.

## Образцы и шаблоны

Архивы читаются непосредственно, без распаковки по потенциально опасным именам. Корпусные хеши и скриншоты не считаются автоматически подтверждённым фишингом. В предоставленном дополнительном архиве связаны 396 писем и 556 сохранённых страниц; из них импортированы шаблоны поведения. DOM, текстовые шинглы и типы полей используются совместно, а совпадение даёт только предупреждение.

```powershell
.\.venv\Scripts\python.exe -m antiphish import-corpus "C:\Users\Max\Downloads\target_brands (1).zip"
.\.venv\Scripts\python.exe -m antiphish learn-template "C:\Mail\reviewed-fake.html" --label phishing
.\.venv\Scripts\python.exe -m antiphish learn-template "C:\Mail\reviewed-normal.html" --label benign
```

Отрицательные образцы отменяют похожее срабатывание шаблона, но не отключают точный подтверждённый IOC или независимое доказательство кражи секрета. `build-kb --case-dir ...` сохраняет ручные записи, шаблоны и отдельные фиды; сборка проходит в промежуточной SQLite, чтобы ошибка не уничтожила прежнюю базу. Для отдельной базы поддерживается `--kb`.

## Профили и локальные модели

| Профиль | Анализ |
|---|---|
| `fast` | Уменьшенные лимиты, без OCR и QR, без изображений документов |
| `quality` | Полный разбор, QR, OCR и вложения; обычный профиль |
| `deep` | Quality плюс локальные Qwen3.5-4B и SigLIP2 |

Профиль меняет полноту, а не порог блокировки. LLM получает факты с привязкой к странице, ограниченные выдержки и при наличии снимок страницы. Она выделяет структурированные факты и точные цитаты; некорректный JSON и отсутствующие в источнике цитаты отбрасываются. Инструкции письма считаются недоверенным содержимым. SigLIP показывает кандидатов бренда, а не подтверждение фишинга. Эти модели не обучались заново на неразмеченном архиве и не блокируют самостоятельно.

Для `deep` нужны дополнительные зависимости (`pip install -e ".[deep]"`) и заранее размещённые каталоги `models/Qwen3.5-4B`, `models/siglip2-base-patch16-224`. Загрузка моделей использует `local_files_only`; письма не отправляются API. Потребление времени и памяти отражается в JSON. `deep` заметно медленнее обычного анализа.

## Проверки качества

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m antiphish benchmark
.\.venv\Scripts\python.exe -m antiphish benchmark-corpus "C:\Users\Max\Downloads\target_brands (1).zip" --profile quality --output reports\target-brands-quality.json
```

`benchmark-corpus` использует пустую KB и только записанные ответы, без живых переходов и подгонки по хешам. Раздельно считает вердикты письма, доступного маршрута и всех сохранённых страниц, статусы полноты и фактически достигнутые страницы. Российская часть выделяется отдельно. Архив использовался при разработке и не является независимой тестовой выборкой; метки поставщика не делают легитимную промежуточную страницу, заглушку или страницу ошибки фишингом. Доля предупреждений по этим меткам не называется recall.

Проверка на 4150 письмах официального SpamAssassin ham дала ноль блокировок и ноль предупреждений. 95%-я верхняя граница для доли блокировок при таком объёме — около 0,0722%; наблюдаемый ноль не доказывает ноль в эксплуатации. Это англоязычный архив 2003 года, а не современные российские легитимные письма. Русские парные сценарии, официальные формы, акции, бухгалтерские письма, обучающие материалы, OCR и динамические формы проверяются отдельными регрессиями.

Контрольные JSON находятся в `reports/`. Для EML с Wildberries подтверждено раскрытие маршрута Google Sheets → опубликованная ячейка → Google `/url` → внешний сокращатель. Исторический конечный сайт не посещался; если он недоступен, отчёт честно указывает неполную сетевую проверку.

## Перенос и данные

Wheel включает каталог брендов и правила, но не письма, архивы, большие модели или чужие репутационные списки. В установленной копии данные по умолчанию хранятся в `%LOCALAPPDATA%\AntiPhish`; в исходном проекте — в его каталоге. Пути можно задать через `ANTIPHISH_DATA_DIR` и `ANTIPHISH_MODEL_DIR`.

JSON не содержит полных MIME/HTML, служебных адресов навигации или снимков; публичные URL скрывают токены. Он содержит имя файла, объяснения и при deep отдельные цитаты, поэтому его следует хранить как результат анализа письма. Автоматическая запись исходных писем и отправка во внешние LLM отсутствуют.

Недоступные страницы, CAPTCHA, зашифрованные вложения, закрытые таблицы, серверные многошаговые формы, телефонное мошенничество без проверяемых фактов и новые бренды могут остаться нераспознанными. Программа показывает эти ограничения; проверку надёжности на современной русской легитимной почте следует расширять реальными независимо размеченными письмами.
